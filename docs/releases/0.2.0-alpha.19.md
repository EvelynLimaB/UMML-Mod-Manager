# Uma Mod Manager 0.2.0-alpha.19 Community Test

This is a **testing prerelease** for players and mod creators willing to provide specific, reproducible feedback. It is not a stable recommendation for unattended use or irreplaceable game data.

The Debian package reports `0.2.0~alpha19`. Windows, AppImage, AppStream, and the Git tag use `0.2.0-alpha.19` / `v0.2.0-alpha.19`.

## Why this release exists

Alpha19 turns the current Manager foundation into a repeatable public testing programme:

- exact release metadata is audited before packages are built;
- Windows portable, Debian, and AppImage packages are produced from the same tagged source revision;
- testers receive one explicit test matrix and feedback format;
- Settings can generate a privacy-scrubbed support bundle;
- issue forms request exact build, environment, reproduction, safety impact, and results;
- release notes identify known limitations rather than outsourcing discovery to whoever clicks first.

## Highlights

### Privacy-scrubbed support bundles

Use **Settings → Create support bundle** to create a small ZIP containing build/platform information, configuration-presence flags, high-level library/profile summaries, and read-only diagnostics.

The bundle excludes game assets, mod payloads, downloaded archives, baselines, transaction contents, roster snapshots, raw settings, credentials, and known account identifiers. Inspect `support-report.json` before uploading it because custom names and free-form errors may still contain personal text.

## What to test

The detailed matrix is in [Testing and feedback](../TESTING_AND_FEEDBACK.md). Priority areas for alpha19 are:

1. **Upgrade preservation:** alpha18 to alpha19 without losing library, profiles, settings, workspaces, baselines, or journals.
2. **Automatic preparation:** especially previously failing multi-target and deeply nested community mods, with no manual preparation ritual.
3. **Window behaviour:** Inspect & edit, package builder, configuration, Veteran Roster, and diagnostics must open in focus.
4. **Profile variants:** two profiles selecting different authored variants from one immutable package.
5. **Conflict explanations:** overlapping targets, dependencies, incompatibilities, load order, region, and stale metadata.
6. **Apply/switch/restore:** on expendable or independently backed-up data, including exact vanilla restoration.
7. **Creator workflow:** create/edit/import a new immutable package version without hand-editing JSON.
8. **Support bundle:** create it, inspect it, and verify it contains useful evidence without raw personal/game data.
9. **Windows portable:** launch without development Python and verify folder actions, themes, diagnostics, and support bundle.
10. **Debian/AppImage:** launch on Mint/Debian and Bazzite/KDE, preserve shared Manager data, and verify theme/folder integration.

## Known limitations

- This build has not completed the full stable-release real-mod and destructive-recovery corpus.
- Hachimi-only packages do not yet have a complete native deployment backend.
- Arbitrary Unity bundle retargeting between characters or dresses is not implemented.
- Character/dress/part detection is evidence-based and may require creator correction.
- GameBanana behaviour can change independently of the Manager and still needs live packaged testing.
- Veteran data remains numeric where current master-database name resolution is unavailable.
- Memory-derived Veteran records may include transient or borrowed context and must not be treated as infallible.
- External UmaExtractor/umadump tools are not bundled where their repository lacks a compatible declared license.
- Runtime injection, live Unity hooks, overlays, and arbitrary executable mods remain outside the desktop Manager.
- Windows installer integration is not provided; the Windows build is portable.
- Signed binaries and signed update metadata are not yet available.

## Safety notes

- Close Umamusume before Apply, restore, baseline, recovery, or write-capable Studio operations.
- Verify SHA-256 checksums before running a downloaded package.
- Keep the previous package for rollback.
- Keep an independent backup before testing destructive or recovery scenarios.
- Do not upload copyrighted game files, decrypted databases, private roster data, credentials, or third-party mods without permission.

## How to report feedback

Use the repository's **Testing feedback** issue form and include:

- exact `MANAGER_VERSION`;
- package filename and SHA-256;
- operating system, desktop, package format, game region, and installation layout;
- clean install or upgrade path;
- numbered steps;
- expected and actual results;
- whether game or Manager data changed;
- a privacy-reviewed support bundle;
- links to relevant mods when redistribution permits linking.

Successful passes are welcome. Silence does not distinguish “works perfectly” from “nobody found the button,” a distinction software projects routinely discover too late.
