# Uma Mod Manager 0.2.0 alpha20 Community Test

Alpha20 is a testing prerelease focused on workflows that should require far
less ceremony than they did in alpha19:

1. installing a supported Veteran roster extractor from its downloaded source
   ZIP;
2. browsing and downloading mods while GameBanana is experiencing a temporary
   API outage;
3. opening Discover and immediately seeing useful catalogue content without a
   required manual Browse step.

It also adds visible release-asset download counters for project feedback.

## Exact version forms

```text
Manager / Debian: 0.2.0~alpha20
Portable / AppStream: 0.2.0-alpha.20
Git tag: v0.2.0-alpha.20
```

Do not relabel alpha19 packages. Alpha20 packages must be built from and reported
against one exact revision with their published SHA-256 values.

## Managed Werseter source ZIP installation

In **Studio → Veteran roster**, use **Install or choose extractor** and select the
upstream `umadump-<version>.zip` source download directly.

For a recognized Werseter package, the Manager now:

- validates the ZIP and rejects traversal, links, special files, duplicate paths,
  encryption, and unsafe sizes;
- detects the project root and upstream version;
- records the source archive SHA-256;
- installs the source into a hash-addressed Manager-owned tools directory;
- creates a private Python 3.14 environment when a compatible interpreter is
  available;
- installs only the upstream `requirements.txt` into that private environment;
- launches the tool outside the Manager process with update checks disabled;
- directs generated JSON into the isolated Veteran inbox;
- imports the latest valid roster automatically after a successful run;
- keeps re-selecting the same archive idempotent.

The upstream source is not bundled in Uma Mod Manager packages. The user supplies
the downloaded archive, and all original project credits and licensing boundaries
remain in force.

### Important runtime limitation

Werseter/umadump 2.5.4 declares Python 3.14 or newer. Alpha20 can create and manage
its private environment, but it does not install Python system-wide. When no
compatible interpreter exists, source installation succeeds safely and the UI
explains that Python 3.14 or a standalone upstream executable is still required.

## GameBanana outage handling

Discover now treats temporary provider failures as provider failures rather than
as evidence that the user's library has ceased to exist.

- Transient HTTP 429, 500, 502, 503, and 504 responses receive a bounded retry.
- The v11 API receives a short circuit after a repeated outage so each result does
  not hammer the same dead endpoint.
- Mod details fall back to GameBanana's independent Core `Item/Data` API.
- Recent catalogue pages continue to use the existing Core `List/New` fallback.
- Core file maps are normalized into ordinary selectable downloads.
- Successful catalogue pages and details are cached for at most fourteen days.
- A live outage may display recent valid cached results.
- Failed file transfers remove their partial `.part` files and never enter the
  immutable mod library.
- Exhausted failures explain that no game files were changed and that a manually
  downloaded archive can still be imported.

During a v11 outage, fallback browsing covers recent submissions and local
filtering. It does not claim complete historical full-text search coverage.

## Discover and general UI experience

The GameBanana catalogue now refreshes automatically shortly after the Manager
launches. It runs as an independent read-only background operation, so game
detection, Library use, Studio tools, and local imports remain available while the
network request is in progress.

- Opening Discover no longer requires pressing **Browse** before anything appears.
- The manual action is now labelled **Refresh**.
- Changing region or sorting resets to page one and refreshes automatically.
- The first result is selected automatically so its metadata, preview, and files
  are immediately useful.
- Refreshes preserve the current selection when that submission remains present.
- Install and catalogue paging are disabled while a refresh is replacing the
  result set, preventing actions against stale rows.
- Background catalogue updates change the footer only while Discover is the active
  page.
- Empty, loading, no-result, and provider-failure states are shown inside the page
  instead of replacing the workflow with a modal error.
- The selected sort order is persisted.
- Region, download-file, and local-folder labels are clearer.
- Library, Discover, local-candidate, conflict-plan, and diagnostics views now
  expose missing horizontal or vertical scrolling where their content can exceed
  the window.
- Diagnostics uses the product name, receives focus, supports Escape to close,
  and no longer opens as an easily lost background window.
- GUI smoke tests explicitly disable background networking.

## Download counters

`docs/DOWNLOADS.md` contains live badges for all uploaded release assets and for
individual Community Test tags. GitHub's generated source ZIP/TAR links are not
normal release assets and are not included in those counters.

The project does not add separate user analytics merely to acquire more flattering
numbers.

## What to test

### Extractor ZIP

1. Start from alpha19 or a clean Manager data root.
2. Open **Studio → Veteran roster**.
3. Select a real Werseter source ZIP through **Install or choose extractor**.
4. Confirm the window remains responsive while validation and environment setup
   run.
5. Confirm the installed provider, version, and runtime status are understandable.
6. Re-select the same ZIP and confirm it does not create a duplicate installation.
7. With Python 3.14 available, run the extractor while the game is on a compatible
   screen and confirm output imports automatically.
8. Inspect the imported snapshot for privacy scrubbing and correct provider
   provenance.

### GameBanana and Discover

1. Launch the Manager and confirm the Global catalogue begins loading without
   opening Discover or pressing Refresh.
2. Open Discover and confirm the page shows a useful loading state, results, or an
   inline provider-failure state rather than a blank table.
3. Confirm the first returned mod is selected automatically.
4. Change Global/Japan and sorting; confirm page one refreshes automatically.
5. Search, change pages, inspect previews, and select a specific file.
6. Refresh while a mod is selected and confirm that selection is preserved when
   the mod remains in the result set.
7. Confirm Install, Previous, and Next are unavailable while a refresh is in
   progress.
8. Switch to another page during refresh and confirm its footer status is not
   replaced by the background catalogue task.
9. Install one disposable mod archive.
10. Repeat while one provider endpoint is unavailable, when practical.
11. Confirm cached results are labelled as fallback data.
12. Confirm a failed download leaves no imported package and no surviving partial
    archive.
13. Confirm local archive import remains available during a provider outage.

### Existing deployment workflows

Re-test automatic preparation, profile planning, Apply, switching, restoration,
and recovery. Provider work must not weaken the transactional deployment rules
merely because two network endpoints were having a difficult afternoon.

## Known limitations

- Alpha20 remains a Community Test and is not a stable recommendation for
  unattended use or irreplaceable data.
- Python 3.14 is not installed system-wide by the Manager.
- Linux process-memory policy may require the extractor to be run separately;
  the Manager itself must not be elevated.
- GameBanana fallback search is not a complete substitute for the searchable v11
  catalogue.
- Cached provider metadata can be stale.
- External extractor outputs remain memory-derived data and require validation.

## How to report feedback

Use **Settings → Create support bundle**, inspect the generated report, and submit
the structured testing form. Include:

- exact alpha20 artifact filename and SHA-256;
- operating system and desktop environment;
- upgrade or clean-install starting state;
- extractor ZIP filename and upstream version when relevant;
- GameBanana region, query, page, sort, and selected submission when relevant;
- exact steps, expected behavior, actual behavior, and whether any game or Manager
  data changed.

Successful passes are useful evidence too. Silence remains compatible with both
perfection and nobody testing the feature, which is not a particularly actionable
ambiguity.
