# Uma Mod Manager 0.2.0 alpha22 Community Test

Alpha22 packages the audited responsive UI, Veteran Roster, importer hardening, and the current GameBanana browser-assisted download bridge into one Windows/Linux Community Test release.

This release deliberately keeps the browser-assisted GameBanana path as the supported interim behavior. Official `uma-mod-manager:` one-click / Remote Install registration is planned separately and is **not** claimed by alpha22.

## Exact version forms

```text
Manager / Debian: 0.2.0~alpha22
Portable / AppStream: 0.2.0-alpha.22
Git tag: v0.2.0-alpha.22
```

Do not mix alpha21 or development-artifact hashes with this release. Report alpha22 only with the exact artifact filename and SHA-256 published on the release.

## GameBanana downloads

GameBanana does not consistently expose anonymous `/dl/<file-id>` or `/mmdl/<file-id>` routes as raw archive responses. Some files return browser-only HTML instead.

Alpha22 therefore uses a two-stage download strategy:

1. The Manager first attempts the normal verified HTTPS provider transfer.
2. If GameBanana returns browser-only HTML, the Manager opens the selected GameBanana file URL in the user's real browser, watches the normal Downloads directory, waits for the completed archive, verifies expected filename, byte size, and MD5 when GameBanana publishes them, then imports the archive with the original submission/file provenance.

The Manager ignores `.crdownload`, `.part`, `.download`, `.partial`, `.tmp`, old files, unrelated archives, and symlinks. AppImage browser launches use a sanitized host environment so Firefox/Chromium do not inherit PyInstaller runtime library paths.

The browser-assisted bridge is intentionally temporary. Mature GameBanana managers receive the archive URL through a registered custom protocol or Remote Install connection; Uma Mod Manager will move to that model after the protocol handler and GameBanana-side registration are complete.

## Discover and provider improvements

- GameBanana catalogues load automatically and keep explicit refresh controls.
- Global/Japan selection, sorting, search, previews, file selection, and provider metadata remain available.
- Download counts are hydrated from detailed records instead of displaying partial catalogue zeros as real totals.
- Provider retries, Core API fallback, bounded cache use, TLS verification, partial-file cleanup, and source hashing remain enabled.
- Standard UMML packages and recognized loose legacy archives share the same verified import boundary.

## Veteran Roster redesign

The roster is now a full workspace rather than a raw JSON table:

- maximized responsive layout with retractable setup, filter, and summary panels;
- focus mode for giving the roster/detail workspace most of the screen;
- cached portraits and local-first portrait extraction from installed game data;
- optional explicit online artwork fallback;
- readable evaluation ranks such as `S`, `S+`, `SS`, and higher tiers;
- aptitude grades shown as `G` through `S` instead of storage integers;
- factor names, descriptions, and exact `1–3★` rarity resolved from the installed `master.mdb`;
- extractor `level: 0` factor placeholders fall back to master rarity instead of inventing `0★` factors;
- skill acquisition levels are displayed as `Lv N`, not stars;
- search, sorting, legacy shortlist, factor/skill filters, pin/compare, same-character filtering, JSON/CSV export, and shared factor/skill comparisons;
- local portrait preload deduplicated by unique costume/card ID.

The installed master database, metadata, and asset bundles are opened read-only. Generated artwork is written only to the Manager cache.

## Importer and safety audit

Alpha22 carries the full importer audit:

- regular local folders;
- ZIP;
- TAR, TAR.GZ, and TGZ;
- unambiguous nested mod roots;
- GameBanana standard and loose-legacy packages;
- managed Werseter source ZIPs;
- Veteran JSON from UmaExtractor/Werseter, including wrapped arrays and known sibling-output recovery;
- immutable re-import and version coexistence.

Additional hardening includes symlink/junction rejection, archive traversal and case-fold/Unicode collision checks, snapshot integrity hashing, atomic exports, read-only SQLite access, safe `meta`/`dat` path containment, cache link protection, and cleanup of stale Tk callbacks.

RAR and 7z remain unsupported by the native importer in this release.

## Standalone Werseter runtime

The alpha21 standalone extractor work remains included. Supported user-supplied Werseter source ZIPs run through the packaged Python 3.14 runtime with `minidump 0.0.24`; no separately installed Python is required in the Windows portable, Debian, or AppImage packages.

The Manager still does not redistribute Werseter's unlicensed upstream source. The user supplies the archive, and the tool runs as a separate process with the current account's normal permissions.

## Known limitations

- Alpha22 remains a Community Test prerelease, not a stable recommendation for unattended or irreplaceable setups.
- Official GameBanana `uma-mod-manager:` one-click and Remote Install integration are not registered yet. Browser-assisted download is the supported interim fallback for browser-only GameBanana files.
- Browser-assisted adoption expects the browser to save into the normal user/XDG Downloads directory unless `UMML_GAMEBANANA_DOWNLOAD_DIR` is set.
- Live GameBanana behavior remains external to the Manager and can change independently.
- Linux ptrace/process-memory policy can prevent external extractors from attaching to the game; the Manager must not elevate itself to bypass that policy.
- RAR and 7z package import are not supported by the native importer.
- Hachimi-only packages do not yet have a complete native deployment backend.
- Arbitrary Unity bundle retargeting between characters or dresses is not implemented.
- Signed binaries and signed update metadata are not yet available.

## Safety notes

- Close Umamusume before Apply, restore, baseline, recovery, or write-capable Studio operations.
- Verify SHA-256 checksums before running a downloaded package.
- Keep the previous application package for rollback.
- Keep an independent backup before destructive or recovery tests.
- Do not upload copyrighted game assets, decrypted databases, private roster data, credentials, or third-party mods without permission.
