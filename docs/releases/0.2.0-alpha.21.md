# Uma Mod Manager 0.2.0 alpha21 Community Test

Alpha21 turns the supported Werseter/umadump source-ZIP workflow into a genuinely
standalone application feature. The Manager packages the required Python 3.14
runtime and `minidump 0.0.24`, while the extractor source itself remains supplied
by the user and credited to its original developers.

It also carries forward alpha20's automatic Discover loading, resilient
GameBanana provider, preparation recovery, and Inspect & edit compatibility fixes.

## Exact version forms

```text
Manager / Debian: 0.2.0~alpha21
Portable / AppStream: 0.2.0-alpha.21
Git tag: v0.2.0-alpha.21
```

Alpha20 packages do not contain the standalone extractor host. Report alpha21
only against one exact artifact filename and SHA-256.

## Standalone Werseter source-ZIP workflow

In **Studio → Veteran roster**, select the downloaded upstream
`umadump-<version>.zip` through **Install or choose extractor**.

For a recognized package, Uma Mod Manager now:

- validates bounded ZIP structure and rejects traversal, absolute paths, links,
  special files, encryption, duplicate paths, and unsafe sizes;
- identifies the Werseter project root and version;
- records archive SHA-256 and immutable local provenance;
- installs the user-supplied source under a hash-addressed private tools root;
- runs supported source through a separate packaged Python 3.14 host;
- bundles `minidump 0.0.24`, the only dependency declared by Werseter 2.5.4;
- rejects source packages that declare dependencies outside the supported
  allowlist instead of running `pip` behind the user's back;
- disables upstream update checks for the managed run;
- confines generated output to the Veteran inbox;
- imports the latest valid roster automatically after success;
- upgrades source installations created by older alpha builds to the bundled
  runtime without requiring the ZIP to be selected again.

The Windows portable, Debian package, and AppImage require no separately installed
Python for this supported workflow.

## Runtime safety and verification

The bundled host is intentionally narrow. It accepts only a regular project-root
`main.py` with the expected Werseter sibling files, validates the requirements
contract, rejects symlinked project or inbox paths, and runs in a separate process
from the GUI.

Every finished package must pass a machine-readable runtime probe. The probe
verifies Python 3.14+, confirms `minidump 0.0.24`, executes a synthetic recognized
source tree, checks the isolated working directory and arguments, and marks the
artifact unready if any step fails.

The Manager does not bundle, modify, or redistribute Werseter's unlicensed source.
The user supplies the upstream ZIP. Python and the separately licensed dependency
are part of the application runtime; the scanner remains an external credited
tool.

## Better fallback detection

Source/development installations retain external-interpreter support. They now
probe `python3.14`, `python3`, and `python` by actual version instead of assuming
that only one executable name can possibly contain Python 3.14. Standalone
upstream extractor executables remain supported.

## Included alpha20 fixes

Alpha21 also includes:

- automatic GameBanana catalogue loading after launch;
- automatic refresh when region or sorting changes;
- stale-request rejection and first-result selection;
- inline loading, empty, and provider-failure states;
- bounded retries, Core API fallback, recent cache, and removal of failed partial
  downloads;
- hidden idle progress indication and improved diagnostics focus/scrolling;
- legacy decoder compatibility with both `UMMLApp` and `ModLoaderGUI`;
- cleanup of stale automatic-preparation errors after successful recovery;
- managed installation of source ZIPs and automatic roster import.

## What to test

### Standalone extractor runtime

1. Upgrade from an alpha20 package that already installed `umadump-2.5.4.zip`.
2. Open **Studio → Veteran roster** and run the configured extractor without
   installing Python 3.14 separately.
3. Confirm the old “Python 3.14 was not found” error no longer appears.
4. Confirm the status identifies the bundled runtime.
5. Confirm the extractor runs as a separate process and produces output in the
   Veteran inbox.
6. Confirm valid roster output is imported automatically.
7. Inspect the extractor log when the upstream tool exits unsuccessfully.
8. Re-select the same ZIP and confirm installation remains idempotent.
9. Try a modified fixture declaring an unsupported dependency and confirm the host
   refuses it without changing system Python or running `pip`.
10. Confirm no administrator or root prompt is requested by the Manager.

### Existing workflows

Re-test Discover, one GameBanana download, automatic preparation, Inspect & edit,
profile planning, Apply, profile switching, vanilla restoration, interrupted
transaction recovery, and support-bundle generation.

## Known limitations

- Alpha21 remains a Community Test rather than a stable recommendation.
- Linux process-memory or ptrace policy can still prevent an extractor from
  attaching to the game. Bundling Python does not grant extra operating-system
  privileges, and the Manager must not elevate itself.
- Only the recognized Werseter source layout and supported dependency contract are
  accepted by the bundled host.
- Future upstream versions may require an adapter update.
- The upstream source is third-party code selected and executed by the user.
- GameBanana fallback search is not equivalent to complete historical v11 search.
- Memory-derived roster data still requires validation.

## How to report feedback

Use **Settings → Create support bundle**, inspect the generated report, and submit
the structured testing form. Include:

- exact alpha21 artifact filename and SHA-256;
- operating system and desktop environment;
- clean install or upgrade path;
- extractor ZIP filename, version, and archive SHA-256;
- whether a system Python was installed, even though it should not be required;
- extractor log outcome and whether roster output imported;
- exact steps, expected result, actual result, and whether any Manager or game data
  changed.

Successful reports matter. Otherwise issue trackers become exquisite catalogues of
failure with no evidence that any human ever reached the happy path.
